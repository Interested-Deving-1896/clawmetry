## Unreleased

### Fixed: a remote script piped into a shell is flagged on a fresh install
- `network_egress` flagged a new host only against a learned baseline, so on a cold start `curl -fsSL https://<host>/install.sh | bash` raised nothing, although the call classifier already rated it high. A fetch piped into an interpreter (`sh`, `bash`, `python`, `sudo sh`, ...) from a host the cohort has not settled on now raises a `network_egress` warning with ground `remote_script`, baseline or not. A host the cohort has settled on stays quiet.
- The ATLAS OpenClaw replay moves AML.CS0051 S09-S12 from observed to detected on a cold start, so CS0051 is caught in both runs. The four benign controls stay quiet. Residual gap G1 narrows to CS0049 and G2 now says the finding arrives after the script ran. Closes vivekchand/clawmetry-pro#256.

### Release: git transport flags that run a program are high risk; env dumps naming tokens and a root agent are warnings (2026-09-25)
- **Carries:** #6160 and #6166. Their entries follow.
- Supersedes the earlier carrier #6165, which carried #6160 only and went stale on `CHANGELOG.md` once #6166 merged.

### Fixed: `git --upload-pack` / `--receive-pack` / `--exec` rated high, not medium
- These CLI flags make git run a named program, so `git push --receive-pack=/tmp/evil.sh origin main` is code execution, but it scored `medium` and a `min_risk: high` policy did not hold it. They now score `high` on any subcommand (`--exec` only where it names a pack program; `-u` only on `clone` / `ls-remote`), with the flag named in the reason. The standard `git-upload-pack` / `git-receive-pack` programs stay `medium`.
- Quoting never changes a verdict: the command is unquoted before it is inspected, and a test pins that, closing the validator bypass that stripped single-quoted content. Second half of vivekchand/clawmetry-pro#244.

### Fixed: an environment dump that prints other services' tokens, and an agent already running as root, are warnings
- `credential_access` rated every bare `env` / `printenv` at info. A dump whose output names credentials (`SLACK_TOKEN=`, `OPENAI_API_KEY=`, matched on whole `_`-separated words, so `TOKENIZERS_PARALLELISM` and `SSH_AUTH_SOCK` do not count) is now a warning. Only the count is recorded, never the names or values, and it holds when the values are masked.
- `privilege_change` only matched verbs that change privilege, so an agent started as root never raised anything. A bare identity probe (`whoami`, `id`, `id -u`) whose answer is root or uid 0 now raises `runs as root (uid 0)` at warning. `sudo whoami` stays elevation, not identity.
- The ATLAS OpenClaw replay moves AML.CS0048 S05 (partial) and S06 (observed) to detected in both cold-start and learned-baseline runs, and residual gap G8 is retired. The controls stay quiet. Closes vivekchand/clawmetry-pro#261.

### Release: OpenClaw's own approval prompts reach the Approvals tab (2026-09-21)
- **Carries:** #6102. Its entry follows.

### Added: pending OpenClaw approvals appear in ClawMetry, and deciding here decides there
- **Why:** #1369 asked where OpenClaw keeps its approvals and got no answer from the filesystem: a read-only sweep of `~/.openclaw/` found no approvals file, no policy directory, nothing. The answer is that they are live Gateway state with a documented CLI in front of them, so until now an OpenClaw agent could be sitting blocked on a permission prompt while the Approvals tab showed an empty queue.
- **What:** the approvals watcher imports what `openclaw approvals pending --json` reports, and the existing Approve / Deny buttons route the decision back through `openclaw approvals resolve`. The decision is fail-closed in the right direction: if OpenClaw cannot resolve it, the endpoint returns 502 and the local row is **not** flipped, so the tab never claims a decision that did not reach the agent. "Approve & always allow" maps to OpenClaw's own `allow-always` rather than being remembered only on our side. A row OpenClaw stops listing is marked expired; a row decided here stays decided even if it is still listed.
- **Against the real contract, not a guess:** the entries are `{id, kind, agentId, sessionKey, createdAtMs, expiresAtMs, summary}` under a top-level `approvals` key. Session attribution comes from `sessionKey`, because OpenClaw does not emit `sessionId`, and `createdAtMs` is converted to ISO-8601, because that column is handed to the UI verbatim and every other producer writes a timestamp there.
- **The daemon's CPU budget is the constraint that shaped it:** the approvals watcher thread starts on *every* install, so this poll is paid by everyone, not by people who use the tab. It runs at 10 s (a human reads these prompts; seconds of discovery latency cost nobody anything), skips outright when `openclaw` is not installed rather than spawning the CLI to discover that, backs off an unreachable gateway instead of retrying into it forever, and is switched off entirely by `CLAWMETRY_NATIVE_APPROVALS=0`. The CLI runs in its own process group and the group is killed on timeout, because `openclaw` is a wrapper whose node child otherwise survives as an orphan. That is the live-hit `_EXEC_POLICY_BACKOFF` exists for.
- **Verified:** against a real DuckDB and the real `/api/approvals`, with nothing stubbed but the Gateway's JSON. Two native approvals import; the route returns an ISO `created_at`, a populated `requestor_session_id`, an `args_preview` of the command rather than the raw payload, and runtime/tool/policy context. `?runtime=openclaw` scopes to 2 and `?runtime=claude_code` to 0; re-polling is idempotent; dropping one from OpenClaw's list expires exactly that one. Against the real CLI with the gateway down, the poll returns cleanly, arms the backoff and leaves every existing row untouched. `tests/test_openclaw_exec_policy_gate.py` is 30 tests, each new one confirmed to fail against the pre-fix code.
- **Fixed alongside:** two tests in that file patched a module reference that any earlier `importlib.reload(clawmetry.approvals)` leaves stale, so the decision route shelled out to the real `openclaw` CLI. One failed and the other passed for the wrong reason. `tests/test_audit_producers.py` stubbed `clawmetry.local_store` through `sys.modules` only, which `from clawmetry import local_store` ignores once the real submodule has been imported; it then wrote to the real `~/.clawmetry` DuckDB and lost the audit row it was asserting. Both were order-dependent and pre-existing.
- **Refs:** #1369, #6102. Contributed by @drathava847-beep.

### Added: Guard inventories what your agents load, and flags a new or changed MCP server, skill, plugin or instruction file (2026-09-15)
- **Why:** an agent loads MCP servers, skills, plugins, instruction files and hook files at session start, and any of them can be swapped without the agent calling a tool (OWASP Agentic ASI04, MITRE ATLAS AML.T0010.005 and AML.T0081). `/api/mcp-servers` only listed servers a recorded call used; nothing said what was configured, since when, or that it changed, and `agent_config_tamper` did not notice an edited `CLAUDE.md` or `AGENTS.md`.
- **What:** `clawmetry/agent_inventory.py` reads the documented config files of Claude Code, Codex, Cursor, Gemini CLI, opencode and OpenClaw (MCP servers, `SKILL.md` skill folders, the Claude Code plugin manifest, `CLAUDE.md` / `AGENTS.md` / `GEMINI.md`, hook and settings files) and records each component with its source, readers, declared version, SHA-256 content hash and first/last seen in two new DuckDB tables. The daemon inventories the home configuration and each active working directory at most every 5 minutes (`CLAWMETRY_AGENT_INVENTORY_SECS`; `CLAWMETRY_AGENT_INVENTORY=0` turns it off). The first pass of a scope is a silent baseline.
- **Findings:** a component added or changed after the baseline raises the new workspace kind `agent_component_change` (warning) on running sessions whose runtime reads it. An edited instruction, hook or settings file raises `agent_config_tamper`: `critical` when hook entries changed in a gitignored `settings.local.json`, `warning` when hook entries changed elsewhere, `info` otherwise. Both are matched only by a policy that names the kind and carry framework references.
- **Guard tab:** a "What your agents load" card lists the inventory from the new `GET /api/guard/inventory` (classified cloud-disabled in clawmetry-cloud#2439), with separate messages for "nothing inventoried yet", "could not read the store" and "found nothing".
- **Not stored:** MCP environment and header values (excluded from the hash, so rotating a token is not a change) and command arguments (hashed, never recorded). ClawMetry never starts a component, so MCP tool descriptions are not checked.
- **Torn reads are not changes:** a config file that exists but cannot be read, parsed or is over the size cap keeps its recorded components instead of reporting them removed, and a component that returns with its previous hash is restored without a finding.
- **Verified:** `tests/test_agent_supply_chain_inventory.py` (11 tests, in CI), five of them shown red against a reverted fix. REQ-GOV-SCI-001..003 mirrored into `docs/acceptance_criteria.json`.
- **Refs:** #5947.

A tool call both signals identify is recorded once, from the span, in either order, and a call only one signal reports is kept. `CLAWMETRY_OTLP_CONTENT` sets what received telemetry keeps: `redacted` (default, unchanged), `full` (personal data kept, secrets still masked) or `metadata` (no prompts, responses or arguments, each withheld field labelled). The security posture names the active profile. `clawmetry maintenance rescrub-spans` scrubs older spans on request: it only counts until `--apply` is given, and it changes content fields only.
- **Honest limits:** a tool call with no call id still belongs to the first signal that reported its session. Under `metadata`, Guard cannot read tool arguments that were not stored. A rescrub cannot change copies already sent off the machine, and it does not apply the content profile to old spans.
- **Verified:** `tests/test_otlp_span_parity_sources_content.py` (15 tests, in the CI OTLP receiver job); 13 fail on the previous code. A test decrypts a sample snapshot and finds the span-raised incident, and the real hosted interceptor lists it under the runtime the telemetry names.
- **Refs:** #5938.

### Added: prompt injection is a Guard finding, and untrusted content raises the pre-tool risk tier (2026-09-14)
- **Why:** injection detection was phrase matching in the Security tab scan and an evaluator card. No Guard policy could act on it, and the pre-tool gate rated a call only by what the call itself does, never by what the agent had just read.
- **Detector:** `prompt_injection` (`clawmetry/detector_injection.py`, signatures in `clawmetry/prompt_injection.py`) reads the text of tool results and user-sourced messages. A tool-result match is a warning, a user-message match alone is info, and a high-risk tool call after the match in the same turn makes it critical. The finding names signature ids, their plain labels and the tool; it never repeats the matched text. Runtime-injected context (AGENTS.md, system reminders) is not scanned as a message, and signature text quoted as code or a regex does not fire. Mapped to OWASP LLM01:2026, ASI01 and MITRE ATLAS AML.T0051.000 / AML.T0051.001.
- **Gate:** after MITRE ATLAS AML.M0030, the Claude Code hook reads the tail of the transcript it runs beside and sends the local receiver tool names, counts and signature ids for the current turn, never content. A high-risk call after output from the web, a browser, an MCP server, mail or chat, `curl`/`wget` or `gh issue|pr view`/`gh api` is rated critical; any medium-or-above call after content that matched a signature is rated critical. No context means today's rating. Only a policy the operator declared asks or denies.
- **Measured:** pinned public samples in `tests/fixtures/prompt_injection/public_samples.json`: AgentDojo `important_instructions`, `tool_knowledge`, `injecagent` and `system_message` 27/27 each, `direct` and `ignore_previous` 0/27 each; garak PromptInject 17/20; deepset prompt-injections test split recall 3/60 at precision 3/3. On 300 recent real Claude Code transcripts of one development machine (16,472 tool calls, in-sample): 1 of 16,470 tool results matched, and 268 calls (1.6%) would have been rated higher.
- **Honest limits:** Cursor and Copilot gates and the older `clawmetry hooks run pretooluse` path keep today's rating. The MITRE ATLAS CS0051 replay's forged control markers are not a signature, and the scorecard does not claim this detector catches CS0051.
- **Verified:** `tests/test_detector_prompt_injection.py` and `tests/test_untrusted_content_gate.py` (in CI), including an end-to-end run of the hook against the receiver.
- **Refs:** #5945.

### Added: spend per project, and a budget per project with alerts as it burns (2026-09-14)
- **Why:** a team lead is asked what a project spent on tokens this month and whether it is inside its budget. Every cost figure grouped by runtime, model, session or a per-runtime team label, so two repositories worked on by the same assistant on one machine could not be told apart, there was one budget for the whole machine, and the export had no project in it (#5941).
- **What:** each session's spend is attributed to a project worked out when it is read, from where the session ran: the repository the read-only git reader already recorded, otherwise the directory itself, with the source and a confidence on every project. Sessions with no recorded directory show as Unassigned. Figures carry a label and an opaque id, never the local path. An operator can assign a project or a single session to a named project for a stated period, with a reason; a correction is a new assignment and the earlier one stays in the history. A budget per project declares amount, period (day, week or month), timezone, currency (USD) and basis. Spend counts in the period it happened in on the budget's clock. The daemon records one alert per threshold (50, 80, 100%) per period; the alert says it does not pause, stop or reverse any charge. Every dollar figure is labelled at published rates, not an invoice. `GET /api/usage/export?by=project` adds a CSV with derived, assigned, unassigned and unpriced amounts; usage with tokens and no price is unpriced, not $0.
- **Where:** `clawmetry/project_attribution.py`, `clawmetry/local_store_projects.py` (three new tables), `routes/projects.py` (cloud-disabled, clawmetry-cloud#2438), `routes/usage.py`, `clawmetry/sync.py`.
- **Not in this change:** spend per user, a Usage tab panel and budget editor, currencies other than USD, and cross-team reports on the hosted side.
- **Verified:** `tests/test_project_attribution_budgets.py` (25 tests over a real scratch DuckDB). REQ-OBS-PRJ-001 mirrored into `docs/acceptance_criteria.json`.
- **Refs:** #5941.
